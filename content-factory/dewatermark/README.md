# dewatermark — опциональный шаг: стирание маркировки Claude

> ⚠️ **Требуется отдельный платный ключ — DeepSeek API** (или другой не-Claude рерайтер).
> Модуль по умолчанию выключен: он не запускается сам, его нужно позвать явно.

## Зачем это

С **02.08.2026** Anthropic ставит невидимую маркировку на текст новых моделей Claude —
статистический сдвиг выбора слов по ключу Anthropic (вариация SynthID-Text от Google
DeepMind, требование ст. 50 EU AI Act, действует по всему миру). Метка переживает
копипаст и часть правок.

Публичного детектора на 23.08.2026 нет, Anthropic обещал выпустить инструменты. Риск для
программного контента очевиден: появится детектор — поисковики получат дешёвый способ
разметить и вычистить сгенерированные статьи.

Модуль пересказывает статью другой моделью. У неё другой сэмплер и нет ключа Anthropic,
поэтому статистический сигнал разрушается.

## ⚠️ Чего этот модуль НЕ делает

**Он не доказывает, что маркировка стёрлась.** Проверить это нечем, пока нет детектора.
Модуль меряет прокси-метрику — долю уничтоженных 6-словных цепочек оригинала.
Это аргумент по механике, а не замер.

## Когда его НЕ надо включать

**Если статьи пишет не Claude — не включайте.** Маркировку ставит Claude; Codex, DeepSeek
и другие писатели её не ставят, и рерайт будет чистой тратой денег и времени.

```bash
python3 -m dewatermark --check-writer site.config.yml
```

Скажет `→ пайплайн НЕ нужен` — значит не нужен.

## Как устроен

```
Claude написал  →  [1] рерайтер пересказывает посекционно
                →  [2] механический гейт: числа, ссылки, разметка, объём, стоп-слова
                →  [3] Claude ЧИТАЕТ и выдаёт список смысловых дефектов
                →  [4] рерайтер чинит ТОЧЕЧНО по ТЗ аудита
                →  [5] Claude принимает: есть грубые дефекты — не публикуем
```

Два правила, на которых всё держится:

- **Правит только не-Claude.** Любая правка Клодом вернёт маркировку и обнулит прогон.
  Поэтому «причесать стоп-слова Клодом» после рерайта — нельзя.
- **Принимает только Claude.** Он читает и выносит вердикт; в текст статьи не попадает
  ни один его токен, поэтому маркировку он не приносит.

Заголовки и фронтматтер модели не показываются вообще: вырезаются до вызова и
приклеиваются обратно после. Они завязаны на `toc[].id` и на FAQPage JSON-LD.

## Запуск

```bash
# сначала — нужен ли вам этот шаг вообще
python3 -m dewatermark --check-writer site.config.yml

# одна статья, без записи на диск
python3 -m dewatermark --file content/blog/statya.mdx --dry

# очередь перед публикацией
python3 -m dewatermark --dir content-factory/queue --limit 5

# фабрика без очереди: только свежие файлы, ДО коммита
python3 -m dewatermark --dir content/blog --new-only

# другой рерайтер
python3 -m dewatermark --dir content-factory/queue --rewriter codex
```

Форматы: `.mdx`, `.md`, `.html`. Обработанное помечается в `<папка>/.dewatermark.json`
по хешу — повторный запуск не гоняет одно и то же дважды.

**Место в конвейере — между генерацией и публикацией.** Не внутри генерации (замедлит)
и не после публикации (метка уже в индексе).

## Ключ

```bash
# в content-factory/.env или ~/.config/dewatermark.env
DEEPSEEK_API_KEY=sk-...
```

Берётся на platform.deepseek.com. Новым аккаунтам дают 5 млн токенов на 30 дней —
этого хватит примерно на 300 статей, чтобы попробовать без оплаты.

## Рерайтеры

| Бэкенд | Состояние | Замечания |
|---|---|---|
| `deepseek` | обкатан | ~0,3–1,6 ₽ и 5–8 мин на статью. Тихо вносит смысловые подмены — их и ловит аудит |
| `grok` | обкатан | По смыслу точнее, но агентский CLI протекает рассуждениями в текст (есть фильтр `clean_chatter`). 1 ч 20 мин на статью |
| `codex` | **не обкатан** | Написан по документации `codex exec`, вживую не гонялся. Проверьте на одной статье с `--dry`, прежде чем ставить в поток |

## Сколько стоит

Замер на боевой статье 1 585 слов: вход 14 552 токена (63 % попали в кэш), выход 3 156 →
**~0,53 ₽ по пиковому тарифу DeepSeek**, вдвое дешевле вне пика. На статьях, где гейт
отправляет секции на повтор, доходит до 1,5 ₽.

Деньги здесь не узкое место. Узкое место — время (5–8 минут на статью) и риск дрейфа.

## Предел метода: не всякий текст поддаётся

Доля переписанного сильно зависит от ниши:

| Тип текста | Переписано | Вывод |
|---|---|---|
| Гуманитарный (образование, право, услуги) | 78–92 % | Метод работает |
| Плотная техника (ГОСТы, марки стали, режимы, параметры) | 41–53 % | **Метод не тянет** |

На техническом тексте термины и номера стандартов держат формулировки — переписать их
«другими словами» просто нечем, и маркировка уцелевает вместе с ними. Плюс рерайтер там
чаще ошибается по существу: в замере он подменил «видимый шов» (косметика) на
«ответственный шов» (несущий узел) — для инженерной статьи это грубая ошибка.

Поэтому документ ниже `MIN_REWRITE_DOC` (70 %) не публикуется вовсе: гейт скажет
«переписано мало, маркировка уцелела, смысла публиковать нет». Это не поломка, а честный
отказ — лучше не платить, чем платить и получить помеченный текст с испорченным смыслом.

## Что оно возвращает

`--report out.json` пишет по каждой статье: статус (`published` / `rejected`), долю
переписанного, список найденных дефектов с severity, оставшиеся блокеры, цену и время.
