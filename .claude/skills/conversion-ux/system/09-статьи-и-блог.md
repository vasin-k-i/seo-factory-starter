# Статьи и блог

Две задачи одновременно: **дать дочитать** (это поведенческие факторы и трафик)
и **перевести часть читателей в следующий шаг** (это деньги). Оптимизировать только вторую —
убить первую.

---

## Сколько вообще конвертит контент `B`

First Page Sage, 160+ сайтов, 5 лет, обновлено 11.2024:

| Тип страницы | Конверсия в лид |
|---|---|
| Отраслевой годовой отчёт | **4,8%** |
| Белая книга / методичка | **4,6%** |
| Лендинг | 2,4% |
| **Статья уровня thought leadership** | **2,3%** |
| **Обычный пост в блоге** | **<1%** |
| Вебинар | 1,3% |

Сквозная конверсия SEO-трафика в лид по всей воронке — 0,032%, то есть 1 из ~3 100 визитов.

**Вывод, который меняет контент-план:** разница между «обычной статьёй» и «сильной экспертной»
по конверсии — больше чем в два раза. Пятьдесят проходных статей проигрывают десяти сильным.

## Структура статьи под дочитывание

`A` NN/g: 79% сканируют, 16% читают дословно. Переписывание в сжатый + сканируемый + без рекламной
воды даёт **+124% к юзабилити**.

Правила:
- **Ответ в первом экране.** Перевёрнутая пирамида: главный вывод сразу, обоснование ниже.
  Человек, пришедший из поиска, должен получить ответ до первой прокрутки.
- **Подзаголовки-смыслы.** По одним подзаголовкам должна читаться вся статья.
  «Проблема» → «Почему счёт вырос втрое за один месяц».
- Абзац — одна мысль, 2–4 строки. Списки. Таблицы вместо перечислений через запятую.
- **Оглавление** для статей длиннее ~1 500 слов — и как навигация, и как заявка на глубину.
- Выделение жирным — только смысловых опор, не «важных» слов подряд.
- Иллюстрация каждые 2–3 экрана, но только та, что объясняет.
- Дата публикации и дата обновления, автор с реальным профилем.
- Ссылки на источники — открываются в новой вкладке.

Что убивает дочитывание: попап на первых секундах, автоплей видео со звуком,
липкая шапка на пол-экрана мобильного, реклама между абзацами, «читать далее» на 30% текста.

## Перевод читателя в следующий шаг

**Иерархия действий, от мягкого к жёсткому:** подписка → скачать материал по теме статьи →
пройти квиз/калькулятор → консультация → покупка.

Правило: **действие должно продолжать тему конкретной статьи**, а не рекламировать компанию.
Статья про выбор фундамента → «Скачайте таблицу: какой фундамент под какой грунт», а не
«Оставьте заявку на строительство дома».

Куда ставить:
1. **Инлайн-CTA после того абзаца, где читатель понял проблему** — обычно после 30–40% текста.
   Один, оформленный как врезка, не как баннер.
2. **Конец статьи** — самый релевантный переход (следующая статья по теме + одно целевое действие).
3. **Сайдбар на десктопе** — работает слабо, но бесплатен.
4. **Липкая нижняя полоса на мобильном** — одна кнопка, появляется после 50% прокрутки.

Не ставить: попап на входе, три разных предложения в одной статье, CTA поверх текста.

## Попапы: что говорят данные `B`

Popupsmart, 10 000+ кампаний, 105 млн показов, 01.2024–09.2025:

| Параметр | Значение |
|---|---|
| Средняя конверсия попапа | **3,49%** |
| Хороший результат | 3–8% |
| Отличный | 8%+ |
| Слабый | <1,5% |
| Триггер по времени на странице **30–60 с** | лучший, до +25% к остальным |
| Exit-intent | возвращает 10–15% уходящих |
| Скролл-триггер 10–50% | вовлечение выше, конверсия ниже |
| Лайтбокс | ~3,6% |
| Полноэкранный | ~3,2%, но вовлечение ~13,1% |
| Плавающая полоса | ~0,8% |
| Без тизера, прямой лидген | ~12% |
| С тизером | ~3,4% |
| Новые посетители | в ~1,5 раза выше конверсия |

И ограничитель: **62% ассоциируют частые попапы с раздражением от бренда.**

Практический вывод: **один** попап на сессию, триггер — 30–60 секунд или exit-intent,
предложение по теме статьи, закрытие крупное и очевидное, на мобильном — нижний лист,
а не полноэкранный оверлей (и никогда сразу после загрузки: это ещё и штраф Google за интерстишалы).

## Блог и поведенческие факторы Яндекса `A/C`

Яндекс собирает поведение и в выдаче, и на сайте: CTR сниппета, возвраты в выдачу, время до
следующего клика (dwell time), глубину, повторные визиты, внутренние клики. Патенты
US9501575B2 (click dwell time) и US10909127B2 подтверждают механику.

Отсюда — прямая связь UX статьи и позиций в Яндексе:
- ответ в первом экране → человек не возвращается в выдачу;
- перелинковка на следующую логичную статью → глубина;
- скорость загрузки → меньше отказов;
- отсутствие агрессивных попапов на входе → нет мгновенного возврата.

То есть конверсионный UX и SEO здесь не конфликтуют, а совпадают. Конфликт появляется только там,
где ради лида ломают чтение.

## Метрики статьи

- Дочитывание (скролл 75%) — Метрика/GA4.
- Время на странице против медианы блога.
- Возвраты в выдачу (Вебмастер: «последний клик»).
- Конверсия в микро-действие (подписка, скачивание) отдельно от макро (заявка).
- Клик по инлайн-CTA — отдельным событием, иначе непонятно, работает ли размещение.

- [ ] Есть оглавление для длинных материалов
- [ ] Один инлайн-CTA по теме статьи после 30–40% текста
- [ ] В конце — следующий шаг и следующая статья
- [ ] Попап один, не раньше 30 с или на выходе, закрытие очевидно
- [ ] Ничего не перекрывает текст на мобильном
- [ ] Есть автор, дата публикации и дата обновления
- [ ] Настроены события: дочитывание, клик по инлайн-CTA
